1. Introducción
La gestión de proyectos tecnológicos en entornos cloud requiere un modelo
estructurado que permita coordinar personas, procesos y capacidades técnicas
bajo criterios claros de gobernanza, control y trazabilidad. La creciente
complejidad de las iniciativas, la participación de múltiples stakeholders y la
necesidad de asegurar resultados predecibles hacen indispensable contar con un
framework común que estandarice la ejecución.
El presente Framework establece el modelo corporativo de gestión de proyectos
de Morris & Opazo, alineado a principios PMI, buenas prácticas de gestión y
experiencia práctica en proyectos de migración, modernización, assessments,
POCs e implementación de soluciones sobre AWS.
Este documento define la estructura organizacional del modelo de gestión, los
niveles de responsabilidad, el ciclo de vida del proyecto, los mecanismos de
coordinación entre áreas, el proceso operativo de ejecución y las herramientas
utilizadas para asegurar control, visibilidad y entrega de valor durante todo el
proyecto.
2. Alcance del Framework
El presente Framework Corporativo de Gestión de Proyectos de Morris & Opazo
establece

necesarios para gestionar proyectos tecnológicos de manera estructurada,
controlada y alineada a los objetivos estratégicos de la organización y del cliente.
Este modelo define cómo se gobiernan, coordinan y ejecutan los proyectos
dentro del ecosistema corporativo, estableciendo un marco común que permite
asegurar consistencia metodológica, trazabilidad y visibilidad durante todo el
ciclo de vida.
El framework es aplicable a proyectos cloud, migraciones, modernización
tecnológica, assessments, POCs e iniciativas de implementación, especialmente
en escenarios donde participan múltiples áreas, dependencias técnicas y distintos
niveles de decisión.

Su propósito es proporcionar una estructura clara que permita coordinar equipos,
facilitar la toma de decisiones y mantener control continuo sobre alcance,
tiempos, riesgos, recursos y entregables.
2.1 Orientación a la Entrega de Valor
El framework promueve una gestión orientada a resultados, donde cada
actividad ejecutada debe contribuir directamente al cumplimiento de los
objetivos del proyecto y a la generación de valor para el cliente y la organización.
La planificación y ejecución deben enfocarse en resultados medibles, priorizando
entregables relevantes, cumplimiento de criterios de aceptación y alineación con
expectativas de negocio.
2.2 Gobernanza y Modelo Organizacional
La gestión del proyecto se desarrolla bajo un modelo de gobernanza que define
niveles claros de responsabilidad entre PMO, Líder de Jefes de Proyecto, Project
Manager y equipos técnicos. Esta estructura permite establecer control
organizacional, mecanismos de escalamiento y toma de decisiones alineadas al
nivel correspondiente, incorporando una separación clara entre gobernanza
estratégica, coordinación táctica y ejecución operativa.
2.3 Visibilidad y Control del Proyecto
El modelo promueve visibilidad continua del estado del proyecto mediante
mecanismos formales de seguimiento, reportería y monitoreo. La información
debe mantenerse disponible y actualizada, permitiendo conocer avance, riesgos,
hitos, desviaciones y estado general durante todo el ciclo de vida, facilitando la
toma de decisiones y fortaleciendo la gobernanza organizacional.

proceso de gestión. Durante todas las fases del proyecto deben identificarse

Los roles definidos no solo representan funciones organizacionales, sino también
niveles de responsabilidad dentro del ciclo de vida del proyecto, abarcando desde
la estrategia y supervisión ejecutiva hasta la ejecución técnica.
3.1 Chief Technology Officer (CTO)
El Chief Technology Officer (CTO) corresponde al nivel estratégico dentro del
Framework Corporativo de Gestión de Proyectos y es responsable de asegurar la
alineación técnica, arquitectónica y organizacional de los proyectos ejecutados
por Morris & Opazo.
Su rol se orienta a garantizar que las iniciativas tecnológicas mantengan
coherencia con la estrategia cloud de la organización, las capacidades técnicas
internas y los estándares de calidad definidos. Actúa como máxima autoridad
técnica dentro del modelo de gobernanza y participa en decisiones de alto
impacto relacionadas con arquitectura, riesgos críticos, escalamiento y definición
tecnológica.
Dentro del framework, el CTO no participa en la operación diaria del proyecto,
sino que interviene como instancia de validación, supervisión técnica y soporte
estratégico para proyectos de alta complejidad o criticidad.
Responsabilidades
Gobernanza Técnica
●​ Definir lineamientos tecnológicos corporativos.
●​ Validar alineación técnica de los proyectos.
●​ Aprobar arquitecturas de alto impacto.
●​ Supervisar cumplimiento de estándares cloud.
●​ Participar en comités de proyectos.
●​ Apoyar a PMO y Líder de PMs.
●​ Definir prioridades técnicas organizacionales.

4.3 Project Manager (PM / JP)
El Project Manager corresponde al rol operativo central dentro del Framework
Corporativo de Gestión de Proyectos y es responsable de liderar la ejecución
integral del proyecto durante todo su ciclo de vida, desde la planificación hasta el
cierre formal.
Desde la perspectiva PMI, el Project Manager actúa como integrador del
proyecto, siendo responsable de coordinar personas, procesos, recursos y
decisiones para asegurar el cumplimiento de los objetivos comprometidos en
alcance, plazo, calidad, riesgos y valor entregado.
Dentro del Framework de Morris & Opazo, el PM transforma el alcance
contractual definido en el SOW en un modelo operativo ejecutable, coordinando
al equipo técnico, manteniendo la alineación con el cliente y asegurando que
todas las actividades se ejecuten bajo criterios de control, trazabilidad y
gobernanza.
El Project Manager es el dueño operativo del proyecto y el principal punto de

6. Roadmap de Gestión del Proyecto
El Roadmap de Gestión del Proyecto define el flujo integral bajo el cual se
gestionan las iniciativas dentro del Framework Corporativo de Morris & Opazo,
estableciendo una secuencia estructurada desde la recepción del proyecto hasta
su cierre formal. Este modelo permite asegurar gobernanza, trazabilidad,
coordinación entre áreas y control continuo durante todo el ciclo de vida.
6.1 PMO Intake
El proceso inicia con el PMO Intake, instancia donde la organización recibe
formalmente el proyecto posterior a la aprobación comercial.
Durante esta etapa se valida la información base necesaria para iniciar la
gestión, incluyendo alcance, SOW, costos, horas estimadas, plazos, entregables,
arquitectura preliminar y criterios de aceptación. Asimismo, se revisan
supuestos, restricciones y nivel de complejidad.
La PMO registra el proyecto dentro del portafolio organizacional y lo clasifica
según criticidad, tipo de ejecución y prioridad, asegurando que cumpla con los
requisitos mínimos para avanzar hacia la ejecución.
Durante esta fase, se define formalmente el Jefe de Proyecto y el equipo Cloud
asignado, asegurando una estructura de trabajo alineada con el alcance,
complejidad y requerimientos técnicos de la iniciativa.
6.2 Project Handover
Posteriormente se desarrolla el Project Handover, etapa que formaliza la
transición desde la fase comercial hacia la operación.
Durante esta fase, la PMO actúa como enlace entre el equipo comercial y el
Project Manager, asegurando una transferencia estructurada del conocimiento
adquirido durante la preventa y validando consistencia entre lo comprometido
comercialmente y la capacidad real de ejecución.
