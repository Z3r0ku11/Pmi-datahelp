## 7. ROADMAP ÁGIL - CICLO DE VIDA

### 7.1 Fase 1: Agile Intake & Handover
- **ID:** PHA-AGIL-001
- **Nombre:** Agile Intake & Handover
- **Objetivo:** Recepción, validación y transferencia operativa de la iniciativa
- **Duración objetivo:** No superior a 4 semanas (salvo excepciones justificadas)
- **Responsable:** Equipo comercial → Equipo operativo
- **Actividades:**
  - Consolidar requerimiento comercial
  - Definir objetivos preliminares
  - Establecer alcance esperado
  - Identificar contexto del cliente
  - Mapear stakeholders involucrados
  - Definir sponsor y contraparte técnica
  - Estimar plazos
  - Definir entregables esperados
  - Asignar equipo (preventa, PM, Cloud Team)
  - Transferir información comercial y técnica
  - Identificar antecedentes técnicos, expectativas, restricciones
  - Mapear riesgos iniciales y dependencias

**Criterios específicos:**
- Identificación stakeholders cliente
- Definición sponsor y contraparte técnica
- Estimación preliminar plazos
- Validación inicial capacidades técnicas
- Identificación dependencias relevantes
- Definición preliminar entregables esperados

### 7.2 Fase 2: Discovery
- **ID:** PHA-AGIL-002
- **Nombre:** Discovery
- **Objetivo:** Levantamiento detallado de requerimientos y contexto
- **Responsable:** Project Manager + Cloud Team

### 11.2 Fortalezas del Framework Ágil
1. **Complementariedad explícita:** No reemplaza sino complementa el Framework Corporativo
2. **Principios claros:** 6 principios ágiles bien definidos y articulados
3. **Casos de uso específicos:** Tipos de proyecto claramente identificados
4. **Duración controlada:** Objetivo de máximo 4 semanas
5. **Flexibilidad estructurada:** Balance entre agilidad y governance
6. **Roles adaptados:** Mantiene estructura organizacional con enfoque ágil

### 11.3 Gaps Metodológicos Identificados
1. **Criterios de entrada/salida:** No se definen criterios específicos entre fases
2. **Definición de Sprint:** Se menciona Sprint Planning pero no se define duración ni estructura
3. **Ceremonias detalladas:** Se mencionan pero no se especifican formatos, duración, participantes
4. **Métricas ágiles:** No se definen KPIs o métricas específicas del modelo ágil
5. **Gestión de riesgos ágil:** Mencionada pero metodología no detallada
6. **Definition of Done:** No se establece criterio de "terminado" para entregables
7. **Backlog management:** Se menciona gestión pero no se detalla metodología
8. **Retrospectivas:** Principio de mejora continua pero ceremonia no definida
9. **Escalamiento ágil:** No se define proceso de escalamiento específico
10. **Herramientas ágiles:** No se especifican herramientas para gestión ágil

### 11.4 Diferencias Clave con Framework Corporativo

#### **Duración:**
- **Corporativo:** Sin límite específico, proyectos de cualquier duración
- **Ágil:** Máximo 4 semanas objetivo

#### **Estructura:**
- **Corporativo:** 8 fases estructuradas y secuenciales
- **Ágil:** 6 fases con enfoque iterativo

#### **Documentación:**
- **Corporativo:** Artefactos estructurados y completos
- **Ágil:** Simplicidad operativa, documentación mínima necesaria

#### **Governance:**
- **Corporativo:** Control estricto, gates formales
- **Ágil:** Validación continua, adaptabilidad

#### **Roles:**
- **Corporativo:** Roles corporativos estrictos
- **Ágil:** Roles adaptados + Product Owner Cliente opcional

#### **Casos de uso:**
- **Corporativo:** Proyectos de implementación completa
- **Ágil:** POCs, assessments, workshops, MVPs, migraciones ágiles

### 11.5 Complementariedad Entre Frameworks
1. **Alcance diferenciado:** Corporativo para proyectos complejos, Ágil para iniciativas rápidas
2. **Governance escalable:** Ambos mantienen estructura organizacional Morris & Opazo
3. **Herramientas comunes:** Asana, Timetracker (no explícito en Ágil pero implícito)
4. **Roles base:** PMO, PM Lead, PM, Cloud Team presentes en ambos
5. **Principios alineados:** Ambos orientados a entrega de valor y control organizacional
